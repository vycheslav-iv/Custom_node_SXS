# SXS — спецификация

## 1. Назначение

`SXS` — детерминированный сборщик сценического брифа. Вход: опциональный
`config` от `KonstCharacterConfig` и 1–6 текстовых описаний от
`KonstCharacterMerge`. Выход: `LLM PROMPT` (инструкция внешней LLM),
`MODEL PROMPT` (готовый промпт), `WARN`, `SEED`, `CONFIG` (JSON).

Нода не вызывает LLM, не загружает моделей и не требует torch.

## 2. Файлы

| Файл | Роль |

| `sxs_node.py` | Контракт ComfyUI: `INPUT_TYPES`, `RETURN_TYPES`, `build`, `IS_CHANGED`. |
| `sxs_data.py` | Протокол: типы, группы, матрица правил, пресеты, позы, камера, окружение, стиль. |
| `sxs_phrases.py` | RU/EN фразы, `SYSTEM`, `RULES`, `phrase()`, `t()`. |
| `sxs_compat.py` | Разбор config, пол, количество, пары, тип, делегирование, пресеты. |
| `sxs_brief.py` | Разрешение брифа, `concretize`, сборка `LLM PROMPT`/`MODEL PROMPT`. |
| `web/js/sxs.js` | Подписи combo, сепараторы, WARN-бейдж, disabled при делегировании. |

| `tests/` | Python-песочница, JS-смоук, статический аудит. |

## 3. Контракт ComfyUI

```python
CATEGORY = "My_custom_nodes/SXS"
FUNCTION = "build"
RETURN_TYPES = ("STRING", "STRING", "STRING", "INT", "STRING")
RETURN_NAMES = ("LLM PROMPT", "MODEL PROMPT", "WARN", "SEED", "CONFIG")
```

`INPUT_TYPES`:

- `required`: 95 записей (включая 6 `Пол_N` и 8/8/5 групповых тоглов + 7 тоглов групп фона);
- `optional`: `config` и `char_1…char_6`, все `forceInput=true`, `multiline=true`.

`IS_CHANGED` — sha256 от `json.dumps(kwargs, sort_keys=True)`: любое изменение
входа пересчитывает ноду.

## 4. Поток данных

```
kwargs ──► parse_config ──► resolve_characters ──► resolve_type
      ──► preset merge ──► resolve choices ──► brief dict
      ──► build_llm_prompt / build_model_prompt ──► 5-tuple
```

### 4.1. config

Ожидаемые поля: `master_seed`, `menu_lang`, `gender_female`, `match_nat`,
`match_gender`, `nationality_raw`, `nationality`, `age`, `personality_raw`,
`preamble`. Неизвестные поля игнорируются. Строка не JSON или не объект —
`WARN`, пустой config.

`seed = 0` наследует `master_seed`; иначе используется значение виджета.
Виджет сида имеет `control_after_generate = randomize` — сид случайный по
умолчанию. `Язык_меню = auto` наследует `menu_lang`, если он `ru`/`en`.

### 4.2. Персонажи

Слоты 1–6. Каждый: текст, пол, роль, источник (`slot`). Правила:

- явный `Пол_N` важнее текста;
- `auto` ищет маркеры `woman/man/girl/boy/женщина/мужчина/девушка/парень`;
  при обоих побеждает более ранний;
- `Девушки`/`Парни` = `auto` считает по распознанным; число — точное
  количество; `random` — допустимое;
- `Распределение`: `by_connection` (по подключённым слотам),
  `by_description` (по тексту), `manual` (только явные слоты);
- `Фокус_на` = `auto` выбирает главного по правилам (POV/одиночный/первый);
- `Политика_отсутствующего`: `pov` (не добавлять), `partial` (добрать
  свободные роли), `invent` (досочинить без внешности).

### 4.3. Тип

`TYPE_RULES[type]` содержит `requires` (`toy`, `strapon`, `dp`), `min/max`
участников и допустимые полы. `strict` исключает несовместимые типы;
`soft` оставляет с предупреждением. Ручной тип при конфликте → `WARN` и
безопасный откат.

`TYPE_GROUPS`: `basic`, `same_sex`, `group`, `solo`, `pov`, `bdsm`, `toys`,
`extreme`; выключенная группа убирает свои типы из allowed.

### 4.3.4. Группы с разделителями в комбо-виджетах

Для полей с большим количеством вариантов в комбо-виджете добавлены визуальные
разделители групп (как в Konst_Character_Gen):

- **Тип сцены** (`Тип`): `--- Базовые ---`, `--- Однополые ---`, `--- Групповые ---`,
  `--- Соло ---`, `--- POV ---`, `--- BDSM ---`, `--- С игрушками ---`,
  `--- Экстремальные ---`;
- **Фон** (`Фон`): `--- Простые ---`, `--- Студия ---`, `--- Город ---`,
  `--- Природа ---`, `--- Вода ---`, `--- Комнаты ---`, `--- Фэнтези ---`;

Разделители не являются протокольными значениями — при выборе разделителя
выбирается случайное значение из группы.

На фронтенде варианты комбо-виджета фильтруются динамически в
`applyDisabled`: при отключении группы переключателя (`Тип_группа_*` или
`Фоны_*_вкл`) её варианты убираются из выпадающего списка виджета.
Python-side `resolve_type`/`resolve_finish_target` дополнительно отфильтровывают
недопустимые значения в брифе.

### 4.3.5. Окружение — фоны

Фоны разбиты на группы с независимыми переключателями (`Фоны_*_вкл`). Пул
фона собирается из включённых групп:

- `Простые фоны`: студия, циклорама, белая/чёрная циклорама, лофт-студия,
  минимал-студия, неон-студия, винтажная студия, текстурная стена.
- `Студийные фоны`: фотостудия, интерьерная студия, натуральный свет,
  софтбоксы, реквизит, драпировки, зеркала, колонны, цветы.
- `Городские фоны`: город, ночной город, дождливый город, улица, переулок,
  площадь, промзона, крыша небоскрёба, набережная, клуб, кафе, ресторан,
  метро, вокзал, аэропорт, балкон, задний двор, гараж.
- `Природные фоны`: лес, горы, поле, сад, пустыня, снежный пейзаж,
  цветущий луг, осенний парк, скалистый берег, туманный лес, саванна,
  бамбуковая роща, степь, каньон, пещера, вулкан, ледник, лавандовое поле,
  виноградник, джунгли, японский сад, вересковая пустошь.
- `Водные фоны`: тропический остров, пляж, море, океан, озеро, горное озеро,
  река, водопад, бассейн, фонтан, пруд, болото, морское дно, коралловый риф.
- `Комнатные фоны`: спальня, ванная, гостиная, кухня, библиотека, большой зал,
  балкон, терраса, особняк, лофт, загородный дом, кабинет, мастерская,
  гардеробная, зимний сад, оранжерея, коридор, лестница, веранда, театр,
  музей, галерея, тронный зал, будуар, гостинничный номер.
- `Фэнтези-фоны`: закат, рассвет, золотой час, туман, метель, грозовое небо,
  ночное небо, звёздное небо, лунная ночь, северное сияние, радуга, замок,
  храм, руины, космос, фэнтези-мир, магический лес, древняя крепость,
  туманные горы, подземный грото, мистический портал, сказочный дворец,
  хрустальная пещера, левитирующий остров, проклятое кладбище, астрал,
  подводное королевство, романтический мир.

`plain`, `white`, `black`, `gray`, `gradient` убраны как бессмысленные.

### 4.3.6. Камера — зум

Добавлен режим `macro` в `Зум` — экстремальный крупный план (макрос) на
расстоянии 10–20 см. Для LLM и генерационной модели фраза
`extreme close-up, macro, 10-20cm distance` (RU: «экстремальный крупный
план, макрос, дистанция 10-20 см») добавляется в `MODEL PROMPT` после типа
сцены.

### 4.6. Этап сцены и финал

`Этап_сцены`: `auto`, `start`, `insertion`, `middle`, `finish`, `random`.
`auto` не добавляет фразу; `random` выбирает из допустимых по типу.

- `NON_INSERTION_TYPES` (`oral`, `fingering`, `facesitting`, `bukkake`,
  `solo_f`, `solo_m`) → `start/middle/finish`;
- остальные типы → `start/insertion/middle/finish`;
- тип делегирован LLM или ещё не разрешён → все четыре.

`Куда_кончает`: `auto`, `none`, `inside`, `mouth`, `face`, `breast`,
`body`, `back`, `outside`, `random`. Применяется только при
`Этап_сцены = finish`:

- без мужчины → `none`;
- `solo_m` → `body/outside`;
- `oral` → `mouth/face/breast/body/outside`;
- `bukkake` → `face/mouth/breast/body`;
- `creampie` → `inside`;
- `facesitting` → `body/outside`;
- `fingering` → `face/breast/body/back/outside`;
- иначе → `inside/mouth/face/breast/body/back/outside`.

Невозможное явное значение → `WARN` и детерминированный откат к допустимому.
Этап и цель попадают в `BRIEF` и в `MODEL PROMPT` после типа сцены.

### 4.4. Пресеты

`romance`, `passion`, `pov`, `group`, `bdsm`, `solo`. Пресет заполняет
только нейтральные значения (`auto`, `random`, `none`, `""`, `False`).
Пользовательское значение всегда важнее пресета.

### 4.5. Делегирование

`<группа>_выбирает_LLM = True` превращает поле в
`{"mode": "llm_choice", "allowed": [...]}`.

- `Позы_выбирает_LLM` — `pose`, `gaze`, `who_top`;
- `Тип_выбирает_LLM` — `type`;
- `Камера_выбирает_LLM` — `angle`, `shot`, `focus`, `camera_level`, `pov`,
  `composition`, `crop`, `camera_target`, `zoom`, `camera_position`;
- `Окружение_выбирает_LLM` — `background`, `lighting`, `time`, `atmosphere`,
  `setting`;
- `Всё_выбирает_LLM` — все четыре.

`Свобода_LLM`: `strict` / `from_lists` / `free`.

## 5. Промпты

`LLM PROMPT` — три блока:

1. `[BRIEF]` — JSON без `warnings`: персонажи, counts, type, emotion, tempo,
   camera, pairs, focus и др.
2. `[ALLOWED]` — только делегированные поля и их допустимые значения; если
   делегирования нет — `(none; all values are fixed in BRIEF)`.
3. `[RULES]` — ограничения сцены, совместимости, языка и терминов.

Системный промт (`[SYSTEM]`) не выводится этой нодой — он задаётся отдельно
в workflow или во внешней LLM-ноде.

`MODEL PROMPT` — тот же бриф без LLM-инструкций. `concretize()` заменяет
каждый `llm_choice` на значение из `allowed` по `MD5(seed + key)`.

`CONFIG` — JSON брифа без `warnings`.

## 6. Детерминизм

- Все случайные решения: `MD5(seed + ":" + key)` → целое.
- Один и тот же seed и входы дают одинаковый `MODEL PROMPT` и `CONFIG`.
- `seed` выводится наружу, чтобы прогон можно было повторить.

## 7. Интерфейс и локализация

- Python — EN-источник для `DESCRIPTION`; русские **идентификаторы**
  виджетов (`Тип`, `Поза`, ...) — часть контракта и не переводятся.
- `locales/{en,ru}/nodeDefs.json` содержат `display_name`, `description`,
  `inputs` (подписи/подсказки) и `outputs`.
- Протокольные значения combo не переводятся. RU-подпись выдаёт
  `widget.options.getOptionLabel`.
- `Comfy.Locale` читается при создании ноды; событие `Comfy.Locale.change`
  переприменяет подписи. `Язык_меню = ru/en` переопределяет локаль.
- DOM-сепараторы групп: `addDOMWidget`, `serialize:false`,
  `hideInPanel:true`, высота 26 px. Вставляются перед первым виджетом
  группы, с конца, чтобы не сбить индексы.
- WARN-бейдж: `onExecuted`, читает `WARN`/`warn`/индекс 2; пусто — скрыт.
- Делегированные поля гасятся через `widget.disabled`; сам переключатель
  остаётся доступным, пока не включён мастер.

## 9. Границы

- Нет вызова LLM и нет сетевых запросов.
- Нет проверки «красоты» промпта: это ответственность модели/LLM.
- Нет автоматического обновления `char_N`: текст приходит по проводу.
- Нет negative prompt: негативные ограничения живут в `[RULES]` и `Запреты`.
